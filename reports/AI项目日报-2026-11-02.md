## 体验路径与限制

### Impeccable：从一个组件开始

按[官方 README](https://github.com/pbakaus/impeccable)运行 `npx impeccable install`，选择安装范围与助手，完成后重新加载助手。手动下载时按客户端对应目录放置文件。Codex 的可选 hook 另需客户端授权。

可先用 `critique` 审查现有界面，再用 `polish` 收敛细节；`/impeccable init` 可整理产品上下文，Codex 使用 `$impeccable init`。不要一次重做整站：先对比一个组件的布局、可读性、响应式效果和品牌一致性。规则检测无需模型 Key 不等于整个设计流程无需模型或费用；审查输出也不等于已通过可访问性测试。本期未安装此 Skill。

### ThinkRail：已有 Pi 用户可优先试

[官方源码说明](https://github.com/JetBrains/thinkrail)给出克隆仓库后执行 `bun install`、`bun run dev` 的路径。先准备上述运行时和 Pi 认证，再在测试 Git 仓库中验证一次小变更。Pi 已在此前日报收录，ThinkRail 的关注点是其开发界面与工作流。

核对 SPEC.md、工作区分支和实际 diff 是否一致，再运行项目原有测试。Git worktree 用于分离工作副本，不应当作安全沙箱。完整扩展支持仍属于后续计划，不作为已有能力；模型费用由配置的提供方决定。本期没有连接账户、安装或验证多任务隔离。
