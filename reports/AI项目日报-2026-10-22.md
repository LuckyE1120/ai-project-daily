## 体验路径与限制

### XERJ：让搜索结果能回到原文

从[官方 Install by hand](https://github.com/xerj-org/xerj#install-by-hand)选择平台包，先索引一份小型代码副本。数据目录应放在被索引树之外，避免索引自身存储。官方示例的 `--insecure` 会关闭 TLS 和 API 鉴权，只适合明确的本机开发边界；共享服务应按其认证说明配置，不直接复制该参数公开服务。

建议预先写三个有已知答案的问题，比较结果是否指向正确文件、关键片段是否完整、源码变化后是否更新。作者给出的 token 或模型效果收益没有在本机复现；兼容接口也不代表所有 Elasticsearch 功能完全一致。本期没有启动服务或配置 MCP。

### Spec Kit：按任务选择流程

从[官方 Get started](https://github.com/github/spec-kit#get-started)准备运行环境，在测试项目选择适合的 Agent integration。当前仓库将 SDD、缺陷修复和想法评估作为不同入口：SDD 在核心中，后两者通过对应扩展选择，不必把所有流程串成强制步骤。

可以拿一个网站小功能，明确行为和验收条件后再做计划、任务及实现，检查生成文档是否帮助测试与交付。如果只是已有缺陷，先看独立修复路径。规范完整、流程报告收敛都不等于软件已经通过真实场景验证；本期没有执行这些命令，也不将当前 README 变化写成今天上线。

### OmniVoice：先试听，再评估长配音

优先看[官方 Installation 与 Quick Start](https://github.com/k2-fsa/OmniVoice#installation)，选择在线演示或匹配本机硬件的环境。参考音频应使用自己的或已获授权的录音；模型下载、依赖和推理资源需要单独准备。项目列出的语言覆盖、速度和效果是作者报告，没有据此保证任意语言或本机设备的表现。

先生成短句，人工核对人名、缩写、数字、断句和参考音色，再考虑视频配音。它是语音模型及工具入口，不是完整的视频时间线编辑器，也不代表此前字幕或视频项目已经接入。
